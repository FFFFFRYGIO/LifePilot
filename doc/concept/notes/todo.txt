3. Development
--------------------------------------------------------------------------------

Development points:
- No computation in the official UI — all values read directly from the database (with Redis) or returned by the API with everything needed
- Language packs — Polish, English (JSON files)
- Multi-layer configuration
- Morning and evening routines can be marked failed
- "Time since X" monitors — e.g. since last conversation with parents
- Historical task log — persisted in the database
- Suggestions for worthwhile tasks without a deadline

- Main screen concept:
    - Small tiles showing status only and listing tasks without a deadline
    - Morning routine, once completed, switches at 20:00 to evening routine
- In the afternoon — main tasks view shows the next day's tasks later
- At noon — task rollover: tomorrow's → today's, today's → overdue
- Trainings — can be failed; ad-hoc sessions can appear — expand training monitoring
- Drop green as a status colour — red = bad, yellow = warning; a normal task needs no highlight colour

8. Task structure (data model)
--------------------------------------------------------------------------------

Task structure:
- Body / title text
- Tags — categories are derived from tags
- Optional modes:
    - Due date
        - Date only, or date and time
        - Reminder (1h, 1d, 1m, [custom] before)
        - Recurrence
    - Track time since — example (roller skating): "3 days since I went" → [click] → "0 days since I went"
        - Without colour thresholds — always green
        - With colour thresholds — when yellow, when red
    - No deadline (like shopping-list products)
